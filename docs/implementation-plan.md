# 墨语笔记 · InkScribe Handwritten Note Studio

将用户粘贴的散乱文本或文章，通过 AI 智能解析重构为具有手写真迹质感、排版优美、主次分明的独页手写笔记。融合康奈尔结构化逻辑与随性手账美学，支持中英文手写字体、真实纸张纹理（方格、点阵、横线、牛皮纸、复古羊皮纸等）、AI 辅助提取重点与手绘插图建议，以及自由贴纸拖拽，并支持高清图片导出与剪贴板复制。

## 1. 产品目标与范围

- **目标用户**：学生、考研/考证用户、知识博主、手账爱好者，以及需要制作学习卡片或分享图片的创作者。
- **核心流程**：粘贴文本 → AI 结构化整理 → 生成手写笔记布局 → 手动微调 → 导出或复制图片。
- **核心价值**：将普通文本转换为清晰、具有手账美学的视觉笔记，同时保留原文中的关键事实与逻辑。
- **首期原则**：优先交付稳定、快速、成本可控的文本结构化与笔记渲染体验；将复杂的 AI 绘图、账号体系和云端保存放到后续迭代。

## 2. 已确认的产品决策

- **排版风格**：默认采用混合康奈尔手账（Hybrid Cornell Journal）：左侧为线索与关键词，中间为主体笔记，右侧或底部放置便签、总结和装饰元素。提供经典康奈尔、自由手账、简约手札等布局预设。
- **插图方式**：结合 AI 提供的插图构思与用户手动添加的贴纸/涂鸦。首期优先使用经过审核的内置 SVG 图案和安全的 SVG 生成器；不直接将模型返回的任意 SVG 当作可信 HTML 内容执行或插入页面。
- **导出格式**：支持高清 PNG/JPG 导出（1x/2x/3x）与复制图片到剪贴板。剪贴板功能需在支持的浏览器、安全上下文及权限条件下使用，并提供下载图片作为备用方式。
- **部署方式**：前端静态资源与服务端 API 一并部署到 Cloudflare Workers。API 由 Worker 提供，AI 推理由 Cloudflare Workers AI 提供；不部署独立的 Node.js / Express 常驻服务器。
- **AI 模型策略**：只通过 Cloudflare Workers AI 调用模型。选择价格、输出质量、中文能力、JSON 遵循能力、延迟和上下文长度之间平衡的开源或闭源模型。模型名称不写死在业务逻辑中，使用配置项切换，并以实际可用模型目录、价格和基准测试结果决定生产默认模型。

## 3. 用户体验与视觉设计

### 3.1 主要用户流程

1. **输入文本**：用户粘贴中文或英文文本，选择读书摘抄、会议纪要、课程总结、思想碎片等模板。
2. **AI 整理**：点击“转化为手写笔记”。Worker 验证请求后调用 Workers AI，将原文转换为符合约定 JSON Schema 的笔记结构，包括标题、线索、段落、重点词、总结和插图建议。
3. **生成画面**：前端根据结构化结果进行排版，在纸张画布中渲染文本、底纹、重点标记和插图。
4. **手动微调**：
   - **字体**：中英文手写字体；支持字号、行距、字距、墨水颜色及轻微自然变化。
   - **纸张**：方格纸、横线本、点阵纸、牛皮纸、象牙白纸、纹理纸。
   - **墨水**：碳素黑、钢笔蓝、复古棕、黛绿、波尔多红。
   - **贴纸与涂鸦**：拖拽、缩放、旋转、删除、调整层级。
5. **导出**：生成 1x/2x/3x PNG/JPG，或在浏览器支持时复制图片到剪贴板。

### 3.2 视觉方向

- **整体风格**：温暖、有质感的书房工作台；深色工作区衬托纸张，界面保持简洁。
- **工作台底色**：`#18181B`、`#27272A`。
- **纸张颜色**：`#FDFBF7`、`#F8F4E9`、`#EFE3CE`、`#F5F5F3`。
- **墨水颜色**：`#1C1917`、`#1E3A8A`、`#451A03`、`#14532D`。
- **重点颜色**：`#FEF08A`、`#BBF7D0`、`#FED7AA`。
- **字体**：界面使用清晰易读的 UI 字体；笔记区域加载合适的中英文手写字体。需核查字体授权、中文覆盖范围、字体文件大小和加载失败时的回退方案。
- **自然手写效果**：使用轻微旋转、行距变化和装饰笔触营造手写感；变化幅度需受控，不能牺牲可读性。

## 4. 技术架构

### 4.1 部署架构

```text
┌─────────────────────────────────────────────────────────────┐
│                       Browser / Client                      │
│  输入与模板 │ 笔记画布 │ 字体/纸张/墨水 │ 贴纸工具 │ 导出     │
└──────────────────────────────┬──────────────────────────────┘
                               │ HTTPS / JSON
                               ▼
┌─────────────────────────────────────────────────────────────┐
│                  Cloudflare Workers                         │
│  静态资源托管 / SPA fallback                                │
│  API 路由：POST /api/structure                              │
│            POST /api/doodle                                 │
│  输入验证、限流、错误处理、超时控制、日志与响应规范          │
└──────────────────────────────┬──────────────────────────────┘
                               │ Workers AI binding
                               ▼
┌─────────────────────────────────────────────────────────────┐
│                  Cloudflare Workers AI                      │
│  配置化模型 ID │ 结构化笔记生成 │ 插图构思/元素建议          │
└─────────────────────────────────────────────────────────────┘

客户端本地状态：NoteStore / LayoutEngine
客户端渲染与导出：DOM/SVG/Canvas + PNG/JPG + Clipboard API
部署与配置：wrangler.toml 或 wrangler.jsonc、环境变量/Secrets、Cloudflare 部署流程
```

### 4.2 技术原则

- **单一部署平台**：使用 Cloudflare Workers 发布应用。前端可由 Vite 构建为静态资源，再通过 Workers 静态资源能力提供；具体配置按项目采用的 Workers 静态资源部署方式确定。
- **AI 调用**：Worker 通过 Cloudflare Workers AI binding 调用模型，不从浏览器直接调用 AI，也不向客户端暴露凭据。
- **不依赖独立 Express 服务**：删除原 Node.js / Express AI 后端和 Vite 开发代理作为生产架构的要求。开发环境可以使用 Vite，生产环境 API 由 Worker 实现。
- **API 与模型解耦**：把模型 ID、生成参数、超时与输出 token 上限集中配置；前端只依赖稳定的 API 数据契约。
- **结构化输出**：要求模型按 JSON Schema 输出；Worker 仍需解析、校验和清理输出。模型未能产生合法 JSON 时，执行有限次数的修复/重试，失败后返回可理解的错误，不把未经验证的内容传给前端。
- **插图安全性**：模型优先返回插图描述或受限的图元规格，而非可直接执行的任意 SVG。由 Worker 或客户端的受控生成器将允许的图元转成 SVG；限制节点类型、数量、尺寸和属性，禁止脚本、事件处理器、外部资源和危险 URL。
- **客户端优先**：纸张纹理、贴纸拖拽、排版、画布渲染和导出尽可能在客户端完成，避免把大尺寸图像反复传给 Worker。
- **隐私与成本**：不默认持久化用户粘贴的原文。限制请求体大小和输出长度；避免日志记录原文或敏感内容；设置合理的调用频率、错误处理和成本监测。

### 4.3 Cloudflare Worker API

#### `POST /api/structure`

请求示例：

```json
{
  "text": "用户粘贴的原始文本",
  "template": "reading-notes",
  "language": "auto",
  "style": "hybrid-cornell"
}
```

职责：

1. 检查 HTTP 方法、内容类型、请求体大小及必填字段。
2. 校验模板、语言和样式枚举值，并限制输入长度。
3. 组装模型提示词和 JSON Schema，调用配置的 Workers AI 模型。
4. 校验返回结构、清理字符串并规范化字段。
5. 返回统一格式的 JSON；对超时、限流、模型不可用和输出格式错误返回适当 HTTP 状态码及稳定错误码。

#### `POST /api/doodle`

首期可选接口。输入为笔记核心概念或 `doodlePrompt`，输出为受限的插图描述或安全图元规格。若内置 SVG 图案足以覆盖首期需求，可先不启用该接口，以降低延迟与模型调用成本。

统一错误响应示例：

```json
{
  "error": {
    "code": "AI_OUTPUT_INVALID",
    "message": "无法生成有效的笔记结构，请重试。"
  }
}
```

### 4.4 Workers AI 模型选择策略

不在计划中永久指定某一个模型名称。实施时从当时 Cloudflare Workers AI 可用模型目录中筛选候选模型，并记录评测日期、模型 ID 和价格。

评测至少包括：

- 中文与英文内容整理质量；
- 对 JSON Schema / 指定字段的遵循程度；
- 重点提取准确性，以及是否凭空添加原文没有的事实；
- 平均响应延迟、失败率和上下文长度；
- 每次生成的输入/输出 token 用量及估算成本；
- Workers AI 的实际调用方式、模型可用性和部署环境兼容性。

建议使用小型评测集（中文文章、英文文章、混合语言文本、超长文本、格式混乱文本）对候选模型进行对比。选出性价比最佳的模型作为默认值，并保留通过环境配置切换模型的能力。若某个任务需要更强能力，可在成本允许且 Workers AI 当时支持的前提下，为该任务配置不同模型；不要假设所有模型都具备相同的 JSON 模式、工具调用或多模态能力。

## 5. 数据契约

### 5.1 `NoteStructure`

```ts
type NoteStructure = {
  title: string;
  date?: string;
  cues: Array<{
    keyword: string;
    note: string;
  }>;
  sections: Array<{
    heading?: string;
    content: string;
    highlights: string[];
  }>;
  doodlePrompt?: string;
  doodleSpec?: {
    concept: string;
    elements: Array<{
      type: "line" | "path" | "circle" | "rect" | "arrow";
      // 仅允许约定的坐标、样式和有限属性
      [key: string]: string | number;
    }>;
  };
  summary: string;
};
```

注意：`doodleSpec` 是概念性契约，实施时应为每种图元定义严格的字段和取值范围，不应以开放式任意属性直接生成 SVG。若暂时不实现 AI 图元生成，可只返回 `doodlePrompt`，并从内置图案库选择插图。

### 5.2 `StickerItem`

```ts
type StickerItem = {
  id: string;
  type:
    | "tape"
    | "sticky-note"
    | "paperclip"
    | "star"
    | "coffee-stain"
    | "custom-doodle";
  x: number;
  y: number;
  rotation: number;
  scale: number;
};
```

坐标应使用画布内部统一坐标系；缩放和旋转需在导出时与屏幕预览保持一致。

## 6. 推荐实现顺序

### Phase 1 — 最小可用版本（MVP）

- 搭建前端项目与 Cloudflare Workers 部署骨架。
- 实现 `/api/structure`，通过 Workers AI 生成结构化笔记。
- 建立并验证 `NoteStructure` 数据契约。
- 完成混合康奈尔布局、基础字体/纸张/墨水设置。
- 实现客户端 PNG 导出和可用时的剪贴板复制。
- 加入请求大小限制、输入校验、基础错误提示和调用日志（不记录原文）。

### Phase 2 — 手账编辑能力

- 增加布局预设、贴纸库和拖拽/缩放/旋转。
- 增加更多纸张纹理、字体和墨水选项。
- 改进长文本布局、分页或内容压缩提示，避免文字溢出。
- 完善 2x/3x 导出、跨浏览器兼容和字体加载后的导出一致性。

### Phase 3 — AI 插图与优化

- 对候选 Workers AI 模型进行质量、延迟和成本评测。
- 在必要时启用 `/api/doodle`，先生成插图描述或受限图元规格，再通过安全生成器绘制 SVG。
- 加入限流、缓存（仅用于适合缓存且不含敏感用户数据的结果）、成本监控和性能优化。
- 根据实际使用数据决定是否增加云端保存、历史记录或账号功能。

## 7. 验收标准

- 用户可粘贴中英文文本，并成功生成符合 `NoteStructure` 契约的结果。
- API 由 Cloudflare Worker 提供，AI 请求通过 Workers AI 发起；生产环境不依赖独立 Node.js / Express 服务。
- 模型可通过配置切换，不需要修改业务逻辑。
- 非法 JSON、模型错误、限流、超时和过长输入均有稳定且可理解的错误处理。
- 用户可修改字体、纸张、墨水、布局和贴纸位置，并导出清晰的 PNG/JPG。
- 支持剪贴板复制的浏览器可正常复制；不支持时仍可下载图片。
- AI 返回的插图数据经过严格校验，不会把不可信脚本或任意 SVG 直接注入页面。
- 日志不默认保存用户原文；部署说明包含必要的 Worker 配置、模型绑定、环境变量和发布步骤。

## 8. 实施前需要验证的事项

- Cloudflare Workers AI 当前可用模型目录、模型 ID、定价、限额及目标账户的可用性。
- 候选模型的中文效果、结构化输出可靠性、响应延迟和实际成本。
- 所选 Workers 静态资源部署方式与现有 Vite 项目的兼容性。
- 中文字体的授权、文件体积、跨浏览器显示及导出表现。
- 目标浏览器的剪贴板 API 支持情况，以及 Canvas/SVG 导出时的跨域资源限制。
